# Hudson Street Library

A specialized photography book collection website built with Eleventy and deployed via GitHub Pages.

## Important: This is an Eleventy Site, Not Jekyll

**Critical**: This site uses [Eleventy](https://www.11ty.dev/) (11ty) as its static site generator, NOT Jekyll. The `.nojekyll` file in the root directory tells GitHub Pages to serve the pre-built files without Jekyll processing.

## Repository Structure

```

├── CNAME                     # GitHub Pages custom domain configuration

│   └── [other collections]
│
├── imgs/                     # Image assets
│   ├── books/               # Book cover images

│   ├── comme/               # Comme des Garçons collection images
│   └── [other image folders]
│
├── js/                       # JavaScript files

├── cms/                      # Directus CMS integration (separate system)

├── *.njk                     # Nunjucks template files (Eleventy templates)

```

## How This Site Works

1. **Static Site Generator**: Eleventy (11ty) processes `.njk` templates and data files
2. **Data Sources**: 
   - Books data from `_data/books.csv`
   - News data from `_data/news.json`
3. **Templates**: Uses Nunjucks (`.njk`) templating language
4. **Output**: Eleventy builds everything into the `_site/` directory
5. **Deployment**: GitHub Pages serves the `_site/` directory contents directly

## Build Process

### Local Development

```bash
# Install dependencies
npm install

# Build the site with Eleventy
npx eleventy

# Or run Eleventy in watch mode
npx eleventy --serve
```

### Deployment

The site is deployed automatically via GitHub Pages:
1. Push changes to the `main` branch
2. GitHub Pages serves the pre-built `_site/` directory
3. The `.nojekyll` file prevents Jekyll processing

## Common Issues and Solutions

### Issue: "Unknown tag 'set'" or "Layout 'book.njk' does not exist"
**Cause**: GitHub Pages trying to build with Jekyll instead of serving pre-built files.
**Solution**: Ensure `.nojekyll` file exists in root directory.

### Issue: CSV Parsing Errors
**Cause**: Malformed CSV data with unescaped quotes or incorrect formatting.
**Solution**: Use `books_cleaned.csv` or ensure proper CSV formatting:
- Double quotes around fields containing commas
- Escape internal quotes by doubling them (`""`)
- Consistent column count across all rows

### Issue: Site Not Updating
**Possible Causes**:
1. Build artifacts not committed to `_site/`
2. GitHub Pages cache delay (wait 5-10 minutes)
3. Browser cache (try hard refresh)

## Important Files

- **`.eleventy.js`**: Eleventy configuration - defines how the site is built
- **`_data/books.csv`**: Main data source for the book collection
- **`news.njk`**: Template for the news page (uses Nunjucks syntax)
- **`books.njk`**: Template for generating book pages
- **`.nojekyll`**: Critical file that tells GitHub Pages not to process with Jekyll

## Data Management

### Books Data (`_data/books.csv`)
- Contains book metadata: author, title, publisher, date, etc.
- Must be properly formatted CSV
- Used by Eleventy to generate book pages and listings

### News Data (`_data/news.json`)
- JSON format for news/announcements
- Structure: Array of news objects with title, date, content, etc.

## Working with Templates

Templates use Nunjucks syntax:
```nunjucks
{% set variable = value %}
{% for item in collection %}
  {{ item.property }}
{% endfor %}
```

This is NOT Jekyll/Liquid syntax, which is why Jekyll builds fail.

## Development Workflow

1. Make changes to templates, data, or content
2. Build locally with `npx eleventy`
3. Test the built site in `_site/`
4. Commit all changes INCLUDING the `_site/` directory
5. Push to `main` branch
6. GitHub Pages will serve the updated site
