# Hudson Street Library - Project Instructions

## Critical Rules (Learned from 100+ Fix Commits)

### CSV Data Management

**ALWAYS use CSVHandler for programmatic CSV editing:**
- Use `CSVHandler` class from `scripts/utils/csv-handler.js` for any Node.js script that modifies `books.csv`
- Never use raw csv-parse/csv-stringify - CSVHandler handles quote escaping, multi-line fields, validation, and automatic backups
- This prevents the 57 structural errors that plagued the project before April 2026
- Example: `const handler = new CSVHandler(); const books = await handler.readCSV();`

**Run CSV validation before committing:**
- Always run `npm run test:csv` before committing changes to books.csv
- Pre-commit hook enforces this, but verify manually if bypassed
- A single structural error breaks the entire Eleventy build

**CSV must always have exactly 36 columns per row:**
- Run `node scripts/validate-csv-structure.js` if you manually edit the CSV
- Missing or extra columns cause build failures

### Book Metadata Rules

**Tags MUST be comma-separated:**
- Use format: `"Art, Photography, Zines"` NOT `"Art; Photography; Zines"`
- Template splits on comma: `book.tags.split(',')`
- Semicolons cause all tags to render as a single element instead of individual clickable tags
- Critical for UI function and related books scoring

**image_url must have leading slash:**
- Correct: `/assets/images/books/filename.jpg`
- Wrong: `assets/images/books/filename.jpg`
- Missing slash breaks relative path resolution, causing 404s on book pages
- Multiple commits (71f110f21, e852e74da) fixed this repeatedly

**Cover image filenames follow strict convention:**
- Pattern: `{author_last}_{author_first}_{title}_{isbn}.jpg`
- All lowercase, underscores for spaces, no special characters
- Auto-generated by add-book script, but manual files must match exactly
- Watch for trailing spaces in filenames - causes git/deploy issues

**Description authoring (the book page's main text):**
- The page `description` is ingested from research-asst's `description.extended` (falls back to the short `main`). research-asst authors `extended`; add-book verifies it landed.
- Author it in three beats: **(1) a top-line framing/review sentence** — what the work is and why it matters; it also becomes the Recently-Added snippet (~280-char truncation), so it must stand alone — then **(2) a summary** of the book (contents, approach, publication/exhibition context), then **(3) artist + other-works context** when the artist has a body of work.
- Format with paragraph breaks: descriptions > 500 characters use `<p>` tags with `class="mt-6"` spacing, the framing sentence as the first `<p>`. Never create single-blob descriptions.
- Target ~800–1300 characters for a major book; curatorial voice, matching existing entries.
- After adding, verify this landed. If only the thin `main` summary did (no framing, no artist context), re-run `/research-asst` for that title rather than hand-writing prose.

**Never include prices:**
- The `price` field in CSV should always be empty
- When gathering book metadata, skip price information entirely
- If price data is accidentally added, remove it immediately

**Preserve ALL user-provided metadata:**
- When adding books, preserve all metadata the user provides
- Don't discard information during data entry
- If unsure about a field, include it - don't leave it blank

### Book Addition Workflow

**Use the right tool for the job:**
- Interactive additions: `npm run add` (requires manual input)
- Automated additions: Write Node.js scripts using CSVHandler
- Never try to automate the interactive script via stdin

**Add-book process:**
1. Use `node scripts/add-book-from-text.js --interactive`
2. Include publisher URL when available for better metadata
3. CSV validation runs automatically after adding
4. Verify the image_url has leading slash
5. Check tags are comma-separated

### Image Management

**Cover image workflow:**
- Images stored in `src/assets/images/books/`
- Naming: `author_last_author_first_title_isbn.jpg` (all lowercase, underscores)
- If `image_url` field is empty but file exists, add the path manually
- Always verify images deploy correctly - check live site

### Deployment

**ALWAYS verify GitHub Pages source BEFORE troubleshooting:**
- GitHub Pages source must be set to: gh-pages branch
- Workflow and Pages configuration must match deployment approach
- Changes won't go live if these don't match
- Check: Repository Settings → Pages → Source

**Deployment workflow:**
- Auto-deploys via GitHub Actions on push to main
- Build time: ~5 min (full Eleventy rebuild)
- Upload time: ~5 sec (incremental, only changed files via gh-pages branch)
- Check status: `gh run list --limit 1`

### Git Workflow

**Push directly to main after committing:**
- No need to ask permission after creating a commit
- Just push to main branch immediately
- This is the established workflow for this project

### Backup System (CRITICAL)

**Automated backup protects books.csv:**
- Runs every 6 hours via launchd
- Three-tier protection: local, safe directory (outside project), git commits
- Safe location: `~/.hudson-library-backups/` survives project deletion
- Manual backup: `./scripts/backup-books-csv.sh`
- Check status: `tail -f logs/backup.log`
- Restore: `cp ~/.hudson-library-backups/daily/books_YYYY-MM-DD.csv src/_data/books.csv`

## Key Metadata Fields

**collection_grouping** - Groups thematically related books (e.g., "Ephemera", "Photography", "Magazines")

**tags** - Comma-separated tags for categorization and search (e.g., "Art, Photography, Zines")

**classification** - High-level categorization (used in related books logic)

**accession_no** - Date format: "YYYY-MM-DD" for recent books, "Month YYYY" for older acquisitions
- Controls "Recently Added" ordering on homepage

**publisher_url** - Should point to book page, not publisher home page
- Direct book links provide more value for readers

## Related Books Logic

- Uses metadata-based scoring (not just author name matching)
- Priority: collection_grouping (+10), tags (+2 each), classification (+3), publisher (+2), author (+1)
- Implemented in `.eleventy.js` as `relatedBooks` filter
- Shows top 12 most relevant books
